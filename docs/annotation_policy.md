# Toramon Mask 注釈方針（annotation_policy）v0.1

作成日 2026-11-09。本方針は Toramon Mask の**保護方針**であり、各元モデル（OpenAI privacy-filter / sumeshi jp）の学習上の定義と完全に同一とは仮定しない。差分は §6 に明記する。

## 1. 基本原則

1. **種類と処置を分ける。** 各 span に `label`（何の種類か）と `action`（今回の方針で伏せるか）を別々に付ける。
   - `MASK`: クラウド LLM へ送信する前に必ず置換する。
   - `KEEP`: 種類としては該当し得るが、今回の方針では残す（公開情報・一般語・組織の代表情報等）。
   - `REVIEW`: 判断が割れる例。理由を `note` に残し、主評価の正解には含めない（別集計）。
2. **全日付・全数字・全 URL・全地名を一律に伏せない。** 個人に紐づくものだけを MASK にする。
3. **位置は元文字列の Unicode コードポイント単位、0 始まり、終了位置を含まない。** 正規化後の文字列で位置を定義しない。
4. **主評価は `action=MASK` の span に対する strict span F1。** KEEP 領域をマスクした予測は FP として数える。REVIEW 領域への予測は TP にも FP にも数えない（別集計）。
5. 曖昧なケースは多数決で確定せず、`REVIEW` として保留し人が確認する。

## 2. 共通 8 カテゴリの定義

| label | MASK にする例 | KEEP にする例 |
|---|---|---|
| `private_person` | 個人の姓・名・フルネーム、フリガナ、通称・ニックネーム、個人を指すユーザー名・ハンドル。ローマ字表記、外国人名、旧字体・異体字を含む | 歴史上・公的に周知の人物名（文脈上公開情報）、会社名に含まれる人名（「山田商事」）、役職名のみ（「部長」）、敬称のみ（「様」） |
| `private_address` | 個人の住所・配送先・勤務先以外の所在地、郵便番号（住所の一部として、または単独で個人に紐づく場合）、建物名・部屋番号 | 企業の公開所在地（署名の会社住所は §4 参照）、都道府県・市区町村名だけで個人に紐づかない言及（「東京都で開催」）、駅名・施設名 |
| `private_email` | 個人・顧客のメールアドレス。個人名を含む業務アドレス（t.shibata@…）も MASK | 代表・共用アドレス（info@, support@, sales@）は **KEEP**（組織の連絡先）。ただし個人名を含むものは MASK |
| `private_phone` | 個人の携帯・固定・FAX、国際表記、内線付き、区切りなし、全角 | フリーダイヤル・企業代表番号（0120/0570/0800 や「代表」明記）は **KEEP**。ただし「堀田様携帯」等の個人に紐づく番号は MASK |
| `private_date` | 生年月日、入社日・退職日・採用面接日などの個人のライフイベント日付、受診日、個人の予約日 | 納期・請求日・会議日・公開日・契約期間・バージョン日付など個人に紐づかない日付は **KEEP**。時刻のみ（14:05）は KEEP |
| `account_number` | 個人に紐づく口座番号、顧客番号、会員番号、契約番号、受付 ID、マイナンバー、運転免許証番号、旅券番号、基礎年金番号、保険証記号番号、在留カード番号、社員番号 | 注文番号・伝票番号・問い合わせ番号は **原則 MASK**（個人と紐づく識別子）。製品型番、バージョン、エラーコード、法人番号は KEEP。**請求書番号・見積番号・管理番号**は法人間取引の単位として KEEP とするが、個人宛（B2C）の文脈では REVIEW（v0.1 パイロットのレビューで最も不一致が多かった項目。人手確認で確定する） |
| `private_url` | 個人識別子・トークン・認証情報を含む URL、個人の SNS プロフィール・個人ページ、追跡用 URL（配送追跡の個別 URL を含む） | 企業・製品の公開ページ、ドキュメント URL、一般的なサービス トップページ |
| `secret` | パスワード、API キー、アクセストークン、Bearer、秘密鍵、ワンタイムコード、接続文字列内の認証情報 | 「パスワードを変更してください」等の語のみ、公開済みサンプル値であることが文脈で明らかなもの（REVIEW 寄り） |

### 拡張トラック（主評価に含めない）
`ext_company`（未公開の取引先名）、`ext_project`（未公開案件名）、`ext_health`（病歴・属性）、`ext_other`。基本 8 カテゴリとの優位比較に混ぜない。

## 3. 境界規則（文字単位で判定できるように）

| 対象 | 含める | 含めない | 例（【】が span） |
|---|---|---|---|
| 敬称 | — | 様・さん・氏・殿・先生・御中 | 【山田太郎】様 |
| 助詞・記号 | — | は・の・：・（ 等 | 氏名：【岡部　美奈子】 |
| 役職・部署・会社 | — | 部長・購買部・株式会社 | 購買部 【西村健二】様 / みらい電子の【柴田】です |
| 姓名間の空白 | 含める（全角・半角） | — | 【岡部　美奈子】 |
| 連名 | 個別 span に分ける | 区切り文字（、・/） | 【山田】、【佐藤】、【鈴木】 |
| フリガナ | 別 span（同じ entity_id、subtype=furigana） | 括弧 | 【柴田孝之】（【シバタタカユキ】） |
| 住所 | 郵便番号（〒記号含む）から部屋番号まで連続する範囲 | 「住所：」「お届け先:」等のラベル語、末尾の改行 | 住所:【〒221-0835 神奈川県横浜市神奈川区鶴屋町2-99-1 サンプルレジデンス803】 |
| 住所と氏名の連結 | 別 span | 全角空白 | 【大阪府枚方市香里園町9-99-9】　【池内洋介】様 |
| 郵便番号のみ | 〒を含めて 1 span（private_address） | — | 【〒160-0022】 |
| 電話 | 数字・区切り・括弧・+・内線表記を含む連続範囲 | 「TEL:」「Mail:」等のラベル語、末尾の句読点・括弧 | TEL:【０５２－７６１－４４９８】／ |
| メール | ローカル部からドメイン末尾まで | 末尾の句読点・括弧・全角括弧 | （【taro@example.test】） |
| URL | スキームから末尾まで（末尾の 。）、）は除く） | — | 【https://track.example.test/p/8842xu】 |
| 日付 | 年号・年月日・曜日を含む連続範囲。和暦の「昭和58年4月12日」は全体 | 「生年月日:」等のラベル語、「生まれ」等の助詞 | 生年月日:【昭和58年4月12日】 |
| 識別番号 | 英数字・ハイフンの連続 | 「会員番号:」等のラベル語、番号の先頭に付く記号・略号（「#」「No.」「№」「第」。2026-11-10 追記: 独立レビュー 2 系統が一致して除外していたため明文化。train/dev の正解 135 span は「#」を含んだままで学習データ側の既知の不整合） | 会員番号:【M-882901】、注文 #【48213356】 |
| secret | 値のみ | key= の key 部、引用符 | password="【Pr1v4cy!】" |
| key=value 形式 | 値のみ | key、=、引用符 | API_KEY=【sk-test-xxxx】 |

- 全角文字・半角文字は原文のまま。span の `text` は必ず `text[start:end]` と一致させる。
- Unicode 結合文字・異体字セレクタは基底文字と一体として span に含める。ゼロ幅文字が氏名内に混入している場合も span に含める（除外すると全範囲保護にならない）。
- 同一文書内で同じ人物を指す表記（フルネーム、姓のみ、フリガナ）は同じ `entity_id` を付ける。同姓の別人は別 ID。

## 4. 文脈判断の規則

- **署名ブロック**: 個人名・個人メール・個人携帯は MASK。会社名・会社代表番号・会社住所は KEEP（企業の公開情報）。ただし「会社住所＝個人事業主の自宅」が文脈で明らかな場合は MASK。
- **組織の連絡先（info@, 0120）**: KEEP。評価では元モデルが検出すれば FP。差分は §6 で報告する。
- **引用文**: 引用内の個人情報も MASK。
- **「この情報はマスクするな」等の原文内指示**: データとして扱い、方針どおり判定する。
- **形式不正の番号**: チェックデジットが不正でも「私の口座番号です」等の文脈があれば MASK。形式のみで非機密と決めない。
- **公開情報の混在**: 社名・公的機関名は KEEP。会社名に人名が含まれる場合（「田中建設」）は KEEP。
- **複数人・複数住所**: すべて個別に span 化し、対応関係を entity_id で保持する。

## 5. 負例の定義

- `no_pii`: 個人情報を含まない業務文（金額、型番、バージョン、エラーコード、公開日程、一般的な地名・日付を含む）。
- `pii_lookalike`: 個人情報に似た表現のみを含む文（製品コード、法人番号、代表電話、info@、公開 URL、架空キャラの定型例文など）。

## 6. 元モデルの方針との既知の差分（評価時に別掲する）

| 項目 | OpenAI (O) | sumeshi (S) | Toramon |
|---|---|---|---|
| 日付 | 個人に関連し得る日付を広く検出 | base の DATE 挙動を継承（日付は負例から除外して学習） | 個人のライフイベント日付のみ MASK。他は KEEP |
| 組織の代表番号・共用メール | 検出することがある | 検出することがある | KEEP |
| 住所にラベル語を含めるか | 含めない | 「自然な場合は含める」ことがある（privacy-filter-jp.cpp の docs/finetuning-jp.md） | 含めない |
| 連名・フリガナ | 1 span になることがある | ランタイムで区切り文字分割（不可分後処理） | 個別 span |
| 時刻 | — | TIME を private_date に写像（作者 CATEGORY_MAP） | KEEP |
| 識別番号の範囲 | account_number | マイナンバー等を account_number に集約 | 同じく account_number に集約 |

これらの差分による FP/FN は「方針差」としてエラー分類し、「モデル能力差」と分けて報告する。

### 2.1 パイロットで判明した曖昧点（2026-11-09、人手確認の優先対象）
- 請求書番号・見積番号・受付管理番号（法人取引 vs 個人宛）
- 業務日付と個人日付の境目（会員登録日・契約予定日・利用日・面接日）: 本人のライフイベント（入会・入社・面接・受診・予約）は MASK、取引・納期・会議・公開は KEEP
- 市区町村までの部分住所（単独では KEEP 寄り、個人の居住地として列挙される場合は REVIEW）
- 歴史上の人物名が署名者・担当者として登場する合成文書（PUBLIC_PERSON の誤用。生成仕様の問題として扱い、REVIEW）
- 氏名の内部/前後のゼロ幅文字: 氏名内部は span に含める、前後は含めない

## 7. レビュー手順（要約）

1. 生成元以外の 2 系統が、生成元・候補ラベル・他レビューを見ずに独立レビューする。
2. 照合後、一致＝`auto_reviewed`、不一致＝`auto_reviewed_disagreement`（人手確認キューへ）。
3. 人が確認した例は `human_verified`。修正不能は `quarantined`。
4. レビュー担当には O/S/T-O/T-S の予測を見せない。
